# ShipSense — Ocean Logistics Cost Forecasting System

An ML-powered internal tool for logistics teams. Forecasts ocean freight shipping fees 90 days ahead, identifies the cheapest nearby booking window, and generates client quotations.

---

## Quick Start

```bash
cd frontend
python -m http.server 8080
# open http://localhost:8080
```

`http://localhost:8080` is the **public site** (Home / About / Contact) — no login, no data fetch. The internal app lives at `/app.html`, reachable from the **Sign In** button in the header.

Login/signup requires a real `@goodfortune.com` account backed by Supabase Auth — sign up from the login page if you don't have one yet (see `supabase/README.md` for enabling email auth on the project).

---

## What It Does

### Public site (no login)

**Home**, **About** and **Contact** — three static pages describing the platform, the lane and the model, plus a contact form validated in JavaScript and stored in Supabase's `contact_messages` table. They load no forecast data and no auth SDK, so they stay readable even when the backend is unreachable.

### Internal app (`/app.html`, login required)

1. **New Forecast** — enter an Intended Ship Date and container count
2. **Forecast Result** — see ML-predicted daily rates for ±5 days around your date
3. **Client Quote** — generate a quotation with 20% markup applied
4. **Forecast History** — browse and manage past forecasts
5. **Executive Dashboard** — Forecast tab (ISD-driven KPIs, trend chart, a calendar aligned to real weekdays, daily table, macro slicer) and Historical Data tab (trend chart + table with clear/month/year granularity)
6. **Market Impact** — an exchange-rate slider against the 90-day forecast. Explicitly an illustration, not a model output: the pipeline produces one central path and cannot answer "the fee at a different exchange rate" (see [docs/frontend-user-flow.md](docs/frontend-user-flow.md#page-7--market-impact)), so quotes are never priced from it

## Project Overview

| Property | Value |
|---|---|
| Route | North Europe → US East Coast (Rotterdam → New York) |
| Forecast target | Daily ocean freight rate, USD per 40ft container (FEU) |
| Forecast horizon | 90 days |
| Model | XGBoost regression (time-series, rolling features) |
| Risk analysis | External shock scoring + Vine Copula dependency |
| Frontend | Static site — three public pages + a single-page internal app. HTML, CSS, vanilla JS |
| Data source | Xeneta XSI-C index (XSICNEUE lane) |

## Data Pipeline

ML notebook exports a `ShipSenseWebsiteBundle` (`shipsense_website_bundle.pkl`) → push triggers `.github/workflows/update-forecast-pkl.yml`, which runs `scripts/pkl_to_json.py` → POSTs the forecast into Supabase's `snapshots` table (JSONB, `kind='forecast'`) and the historical actuals into `historical_data` (one row per day) via its REST API → frontend reads both tables directly over PostgREST, no custom server involved. See [supabase/README.md](supabase/README.md) and [docs/data-pipeline.md](docs/data-pipeline.md).

- **Executive Dashboard → Forecast tab** (chart, table, calendar) sources **strictly from Supabase's `snapshots` table** — if Supabase isn't configured or has no forecast snapshot yet, the tab simply shows no data.
- **Executive Dashboard → Historical Data tab** sources **strictly from Supabase's `historical_data` table** — same rule.
- The Shipping Fee Calendar places each forecast row on its true calendar weekday (leaving weekends blank) rather than packing rows 7-per-row in sequence, since the forecast only contains business days.
