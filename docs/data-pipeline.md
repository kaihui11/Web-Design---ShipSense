# Data Pipeline — ML to Frontend

How the XGBoost model output reaches the live frontend.

---

## Overview

Source notebook: an XGBoost training notebook run in Google Colab (maintained externally, not tracked in this repo). It trains the model and exports a `ShipSenseWebsiteBundle` instance, pickled as `shipsense_website_bundle.pkl` (see `docs/data-schema.md` for the object's attribute contract).

The backend is Supabase (hosted Postgres, reachable from anywhere) — see [supabase/README.md](../supabase/README.md).

```
Google Colab (you, manually)
  └── Run notebook → downloads shipsense_website_bundle.pkl
                         │
                         ▼
        Run scripts/pkl_to_json.py (locally, or
        automatically via update-forecast-pkl.yml on push)
        pointed at Supabase (SUPABASE_URL, SUPABASE_SERVICE_KEY)
                         │
                         ▼
   POSTs the forecast into Supabase's `snapshots` table
   (kind='forecast') and historical actuals into
   `historical_data`, one row per day (see supabase/schema.sql)
                         │
                         ▼
   frontend/app.js and frontend/exec-data.js fetch straight
   from Supabase's REST API on next page load ✓
```

`.github/workflows/update-forecast-pkl.yml` auto-runs `pkl_to_json.py` whenever a `.pkl` file is pushed, using the `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` repo secrets.

Both the Forecast tab and the Historical Data tab read Supabase only. If Supabase isn't configured, or `snapshots`/`historical_data` are empty, the corresponding tab simply shows no data — see `docs/after-receiving-pkl.md`.

---

## Step-by-Step: Updating Forecast Data

1. Run the notebook in Google Colab through to the export cell
2. Download `shipsense_website_bundle.pkl`
3. Replace it in the repo root → `git add` → `git commit` → `git push`
4. GitHub Actions (`update-forecast-pkl.yml`) detects the `.pkl` change, runs `scripts/pkl_to_json.py`, which POSTs the forecast + historical rows straight into Supabase
5. Vercel's static frontend needs no redeploy — it reads Supabase directly on every page load

Manual/local run:

```bash
pip install pandas joblib
SUPABASE_URL=... SUPABASE_SERVICE_KEY=... python scripts/pkl_to_json.py shipsense_website_bundle.pkl
```

## Files Involved

| File | Role |
|---|---|
| `shipsense_website_bundle.pkl` | Model output — forecast + historical actuals + metrics (regenerated by an external, untracked Colab notebook) |
| `scripts/pkl_to_json.py` | Converts the `.pkl` → forecast/historical payloads, POSTs to Supabase |
| `supabase/schema.sql` | Supabase `snapshots`, `historical_data`, `quote_requests` tables + RLS policies, see [supabase/README.md](../supabase/README.md) |
| `.github/workflows/update-forecast-pkl.yml` | GitHub Action that auto-runs `pkl_to_json.py` on `.pkl` push |

## GitHub Actions Workflow

File: `.github/workflows/update-forecast-pkl.yml`

**Trigger:** Push to main that changes any `.pkl` file, or manual dispatch with a `pkl_path` input.

**Steps:**
1. Checkout repo (full history — needs `HEAD~1` to detect which `.pkl` changed)
2. Set up Python 3.11, install `pandas`/`joblib`
3. Find the pushed `.pkl` path
4. Run `scripts/pkl_to_json.py <path>` with `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` secrets set

## Frontend Data Loading

`app.js` loads the forecast snapshot on `DOMContentLoaded`:

```js
const res  = await fetch(`${SUPABASE_URL}/rest/v1/snapshots?kind=eq.forecast&select=payload&order=id.desc&limit=1`,
  { headers: { apikey: SUPABASE_ANON_KEY, Authorization: `Bearer ${SUPABASE_ANON_KEY}` } });
const json = await res.json();
FORECAST_DATA = json[0].payload.forecast;
```

`fetch()` requires an HTTP server — it does not work when opening `app.html` directly as a `file://` URL. Use `python -m http.server 8080` for local testing.
